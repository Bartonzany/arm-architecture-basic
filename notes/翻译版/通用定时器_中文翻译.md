## 1. 概述

本指南介绍通用定时器（Generic Timer），即面向 A-profile 处理单元（PE）的定时器框架。本指南介绍现代 SoC 内定时器框架的不同组成部分，并涵盖软件可用的编程接口。

本指南面向编写低层软件来初始化或使用基于 Arm 的系统中定时器的开发者。本指南的使用者通常从事低层代码工作。

在本指南末尾，你可以进行“知识自测”。你将学习构成定时器子系统的不同组成部分的名称和用途。你将能够在裸机环境中编写代码来设置定时器。你还将能够根据已实现的架构特性来描述存在哪些定时器。

## 3. 什么是通用定时器？

通用定时器为 Arm 内核提供了一套标准化的定时器框架。通用定时器包括一个系统计数器（System Counter）和一组每个核的定时器，如下图所示：

![图 3-1：系统计数器](../../asset/figure3-1-system-counter.png)

*图 3-1：系统计数器*

系统计数器是一个常开（always-on）设备，它提供固定频率递增的系统计数。系统计数值被广播到系统中的所有内核，为内核提供对时间流逝的共同视图。系统计数值的宽度在 56 位到 64 位之间。从 Armv8.6-A 和 Armv9.1-A 起，计数的频率固定为 1GHz。在 Armv8.6-A 之前，计数频率是系统设计的选择，通常在 1MHz 到 50MHz 的范围内。

> 通用定时器只测量时间的流逝。它不报告时间或日期。通常，SoC 还会包含一个用于时间和日期的实时时钟（Real-Time Clock，RTC）。

每个内核都有一组定时器。这些定时器是比较器，与系统计数器提供的广播系统计数进行比较。软件可以配置定时器在未来的设定时间点生成中断或事件。软件也可以使用系统计数来添加时间戳，因为系统计数为所有内核提供了一个共同的参考点。

在本指南中，我们将解释定时器和系统计数器的操作与配置。

| 非安全 EL2 物理定时器 | 实现了 EL2 和非安全状态 |

### 4.1 计数与频率

CNTPCT_EL0 系统寄存器报告当前的系统计数值。

对 CNTPCT_EL0 的读取可以是推测性的（speculative）。这意味着它们的读取可能相对于程序流是乱序的。这在某些情况下可能很重要，例如比较时间戳时。当计数器读取的顺序很重要时，可以使用 ISB，如下面的代码所示：

```asm
loop:           // 轮询某些通信，以指示读取定时器的需求
  LDR X1, [X2]
  CBZ x1, loop
  ISB           // 没有这个，CNTPCT 可能在内存位置 [X2] 被写入值 0 之前就被读取
  MRS X1, CNTPCT_EL0
```

> Armv8.6-A 和 Armv9.1-A 增加了一个自同步（self-synchronizing）版本的 CNTPCT_EL0 寄存器，它被称为 CNTPCTSS_EL0。

CNTFRQ_EL0 报告系统计数的频率。然而，这个寄存器不是由硬件填充的。该寄存器在最高的已实现异常级别可写，在所有异常级别可读。固件（通常运行在 EL3）在早期系统初始化时填充此寄存器。更高级别的软件（如操作系统）随后可以使用该寄存器获取频率。

### 4.2 定时器寄存器

每个定时器都有以下三个系统寄存器：

| 寄存器 | 用途 |
| --- | --- |
| `<timer>_CTL_EL<x>` | 控制寄存器 |
| `<timer>_CVAL_EL<x>` | 比较器值 |
| `<timer>_TVAL_EL<x>` | 定时器值 |

在寄存器名称中，`<timer>` 标识正在访问的是哪个定时器。下表显示了可能的值：

| 定时器 | 寄存器前缀 | EL\<x\> |
| --- | --- | --- |
| EL1 物理定时器 | CNTP | EL0 |
| EL1 虚拟定时器 | CNTV | EL0 |
| 非安全 EL2 物理定时器 | CNTHP | EL2 |
| 非安全 EL2 虚拟定时器 | CNTHV | EL2 |
| EL3 物理定时器 | CNTPS | EL1 |
| 安全 EL2 物理定时器 | CNTHPS | EL2 |
| 安全 EL2 虚拟定时器 | CNTHVS | EL2 |

例如，CNTP_CVAL_EL0 是 EL1 物理定时器的比较器寄存器。

### 4.3 访问定时器

对于某些定时器，可以配置哪些异常级别可以访问该定时器：

- **EL1 物理和虚拟定时器：**
  - EL0 对这些定时器的访问由 CNTKCTL_EL1 控制。
- **EL2 物理和虚拟定时器：**
  - 当 HCR_EL2.{TGE,E2H}=={1,1} 时，EL0 对这些定时器的访问由 CNTKCTL_EL2 控制。这些定时器是作为 Armv8.1-A 虚拟化宿主扩展支持的一部分加入的。
- **EL3 物理定时器：**
  - 从 S.EL1 的访问可以使用 SCR_EL3.ST 捕获到 EL3。
  - 从 Armv8.4-A 起，当 SCR_EL3.EEL2==1（安全 EL2 启用）时，定时器从 S.EL1 或 S.EL2 不可访问。从 S.EL1 或 S.EL2 尝试访问定时器将导致 UNDEF。

### 4.4 配置定时器

有两种配置定时器的方法，要么使用比较器（CVAL）寄存器，要么使用定时器（TVAL）寄存器。

比较器寄存器 CVAL 是一个 64 位寄存器。软件向此寄存器写入一个值，当计数达到或超过该值时，定时器触发，如下所示：

```
定时器条件满足：CVAL <= System Count
```

定时器寄存器 TVAL 是一个 32 位寄存器。当软件写入 TVAL 时，处理器在内部读取当前系统计数，加上所写入的值，然后填充 CVAL：

```
CVAL = TVAL + System Counter
定时器条件满足：CVAL <= System Count
```

你可以在软件中看到这种对 CVAL 的填充。如果你读取当前系统计数，向 TVAL 写入 1000，然后读取 CVAL，你会看到 CVAL 大约等于 1000 + 系统计数。计数是近似的，因为在指令序列期间时间会继续流逝。

读回 TVAL 会显示它递减到 0，而系统计数递增。TVAL 报告一个有符号值，并且在定时器触发后将继续递减，这允许软件确定定时器在多久之前触发的。TVAL 和 CVAL 为软件提供了两种不同的定时器使用模型。如果软件需要在时钟的 X 个 tick 后发生定时器事件，软件可以将 X 写入 TVAL。或者，如果软件想在系统计数达到 Y 时发生事件，软件可以将 Y 写入 CVAL。

> 请记住，TVAL 和 CVAL 是编程同一个定时器的不同方式。它们不是两个不同的定时器。

### 4.5 中断

定时器可以被配置为生成中断。来自内核定时器的中断只能投递到该内核。这意味着一个内核的定时器不能用于生成面向不同内核的中断。

中断的生成通过 CTL 寄存器控制，使用以下字段：

- `ENABLE` —— 启用定时器。
- `IMASK` —— 中断屏蔽。启用或禁用中断生成。
- `ISTATUS` —— 当 ENABLE==1 时，报告定时器是否正在触发（Cval <= System Count）。

要生成中断，软件必须将 ENABLE 设置为 1，并将 IMASK 清除为 0。当定时器触发（CVAL <= System Count）时，会向中断控制器断言一个中断信号。在 Armv8-A 系统中，中断控制器通常是通用中断控制器（GIC）。

每个定时器使用的中断 ID（INTID）由服务器基础系统架构（SBSA）定义，如下所示：

| 定时器 | SBSA 推荐的 INTID |
| --- | --- |
| EL1 物理定时器 | 30 |
| EL1 虚拟定时器 | 27 |
| 非安全 EL2 物理定时器 | 26 |
| 非安全 EL2 虚拟定时器 | 28 |
| EL3 物理定时器 | 29 |
| 安全 EL2 物理定时器 | 20 |
| 安全 EL2 虚拟定时器 | 19 |

> 这些 INTID 在私有外设中断（Private Peripheral Interrupt，PPI）范围内。这些 INTID 是特定内核私有的。这意味着每个内核都将其 EL1 物理定时器视为 INTID 30。这在我们的通用中断控制器指南中有更详细的描述。

定时器生成的中断表现为电平敏感（level-sensitive）方式。这意味着，一旦达到定时器触发条件，定时器将继续发出中断信号，直到发生以下情况之一：

- IMASK 被设置为 1，屏蔽中断。
- ENABLE 被清除为 0，禁用定时器。
- TVAL 或 CVAL 被写入，使触发条件不再满足。

在为定时器编写中断处理器时，软件在 GIC 中停用中断之前清除中断是很重要的。否则 GIC 会再次重新发出相同的中断信号。

> GIC 的操作和配置超出了本指南的范围。

### 4.6 定时器虚拟化

之前，我们介绍了处理器中存在的不同定时器。这些定时器可以分为两组：虚拟定时器和物理定时器。

物理定时器，如 EL3 物理定时器 CNTPS，与系统计数器提供的计数值进行比较。此值被称为物理计数（physical count），由 CNTPCT_EL0 报告。

虚拟定时器，如 EL1 虚拟定时器 CNTV，与虚拟计数（virtual count）进行比较。虚拟计数计算如下：

```
Virtual Count = Physical Count - <offset>
```

偏移值在寄存器 CNTVOFF_EL2 中指定，该寄存器只能在 EL2 或 EL3 访问。此配置如下图所示：

![图 4-1：系统计数器](../../asset/figure4-1-timer-virtualization.png)

*图 4-1：系统计数器*

> 如果未实现 EL2，偏移固定为 0。这意味着虚拟和物理计数值始终相同。

虚拟计数允许 hypervisor 向虚拟机（VM）显示虚拟时间。例如，hypervisor 可以使用偏移来隐藏 VM 未被调度时的时间流逝。这意味着虚拟计数可以表示 VM 所经历的时间，而不是墙上时钟时间。

### 4.7 事件流

通用定时器还可以用于生成事件流，作为等待事件（Wait for Event）机制的一部分。WFE 指令将内核置于低功耗状态，内核由事件唤醒。

> 关于 WFE 机制的细节超出了本指南的范围。

有几种方法可以生成事件，包括：

- 在另一个内核上执行 SEV（发送事件）指令
- 清除内核的全局独占监视器（Global Exclusive Monitor）
- 使用来自内核通用定时器的事件流

通用定时器可以被配置为以固定间隔生成事件流。这种配置的一个用途是生成超时。WFE 通常用于等待资源变得可用，当等待预期不会很长时。来自定时器的事件流意味着内核将保持在低功耗状态的最大时间是有限的。

事件流可以从物理计数 CNTPCT_EL0 或虚拟计数 CNTPVT_EL0 生成：

- CNTKCTL_EL1 —— 控制来自 CNTVCT_EL0 的事件流生成
- CNTKCTL_EL2 —— 控制来自 CNTPCT_EL0 的事件流生成

对于每个寄存器，控制项是：

- `EVNTEN`：启用或禁用事件的生成
- `EVNTI`：控制事件的速率
- `EVNTDIR`：控制何时生成事件

控制项 EVNTI 指定 0 到 15 范围内的一个位位置。当所选位置的位改变时，生成一个事件。例如，如果 EVNTI 设置为 3，那么当计数的 bit[3] 改变时生成一个事件。

控制项 EVNTDIR 控制当所选位从 1 变为 0 还是从 0 变为 1 时生成事件。

## 5. 系统计数器

在“什么是通用定时器？”中，我们介绍了系统计数器。系统计数器生成分发给系统中所有内核的系统计数值，如下图所示：

![图 5-1：系统计数器](../../asset/figure5-1-system-counter.png)

*图 5-1：系统计数器*

SoC 实现者负责系统计数器的设计。通常，系统计数器在系统启动时需要一些初始化。Arm 为系统计数器提供了推荐的寄存器接口，但你应该与你的 SoC 实现者核对具体实现的细节。

一个物理系统计数值广播到所有内核。这意味着所有内核共享相同的时间流逝视图。考虑以下示例：

- 设备 A 读取当前系统计数，将其作为时间戳添加到一条消息中，然后将消息发送给设备 B。
- 当设备 B 收到消息时，它将时间戳与当前系统计数进行比较。

在这个例子中，设备 B 看到的系统计数值永远不会早于消息中的时间戳。

系统计数被要求是固定频率的，以便它呈现一致的时间视图。架构使用两个术语来描述计数器的频率：

**有效频率（Effective frequency）**

这表示计数器每个单位所代表的时间量。例如：

- 50MHz 的有效频率意味着计数器每个单位代表 20ns。
- 1GHz 的有效频率意味着计数器每个单位代表 1ns。

在 CNTFRQ_EL0 中报告的正是有效频率，并且不允许变化。从 Armv8.0 到 Armv8.5（含），有效频率通常在 1-50MHz 范围内。从 Armv8.6/Armv9.1-A 起，有效频率始终为 1GHz。

**计数器分辨率（Counter resolution）**

计数器分辨率表示计数器更新的频率。例如，计数器可能具有 1GHz 的有效频率，但实际时钟以 100MHz 运行。这意味着系统计数每 10ns 递增 10。

与有效频率不同，计数器分辨率允许随时间变化。设计可能根据系统的电源状态选择调整计数器分辨率。

> Arm 建议在正常运行中计数器分辨率不低于 50MHz。

### 5.1 计数器缩放

缩放系统计数的选项是在 Armv8.4-A 中引入的。计数不再在时钟的每个 tick 递增 1，而是可以递增 X，其中 X 由软件在系统初始化期间配置。此特性允许计数有效地比计数器频率更快或更慢地递增。

为了支持缩放，系统计数器在内部将计数器值扩展到 88 位，如下图所示：

![图 5-2：计数映像的位整数部分](../../asset/figure5-2-count-image.png)

*图 5-2：计数映像的位整数部分*

计数被表示为一个 88 位定点数，其中 64 位用于整数部分，24 位用于小数部分。计数的整数部分正是所连接处理器上 CNTPCT_EL0 所报告的内容。小数部分由系统计数器在内部使用。

递增量来自一个名为 CNTSCR 的 32 位寄存器，其格式如下所示：

![图 5-3：位整数部分](../../asset/figure5-3-increment-part.png)

*图 5-3：位整数部分*

递增值被分为 8 位的整数部分和 24 位的小数部分。

当启用缩放时，在每个 tick，计数递增 CNTSCR 中的值。例如，如果 CNTSCR 设置为 0x0180_0000，这意味着在每个 tick 计数递增 1.5（整数部分 0x01，小数部分 0x80_0000）。这在下表中说明：

| Tick | 内部计数器值（整数部分 / 小数部分） | 导出的计数器值（通过 CNTPCT_EL0 可见） |
| --- | --- | --- |
| 0 | 0x0000_0000_0000_0000_0000_00 | 0x0000_0000_0000_0000 |
| 1 | 0x0000_0000_0000_0001_8000_00 | 0x0000_0000_0000_0001 |
| 2 | 0x0000_0000_0000_0003_0000_00 | 0x0000_0000_0000_0003 |
| 3 | 0x0000_0000_0000_0004_8000_00 | 0x0000_0000_0000_0004 |
| 4 | 0x0000_0000_0000_0006_0000_00 | 0x0000_0000_0000_0006 |
| 5 | 0x0000_0000_0000_0007_8000_00 | 0x0000_0000_0000_0007 |
| 6 | 0x0000_0000_0000_0009_0000_00 | 0x0000_0000_0000_0009 |

缩放只能在系统计数器被禁用时配置。在计数器运行时改变是否启用缩放、或改变缩放因子，可能导致返回未知的计数值。

### 5.2 基本编程

本节中的指导假设系统计数器实现了推荐的 Arm 寄存器接口。

系统计数器提供两个寄存器帧：CNTControlBase 和 CNTReadBase。

寄存器帧 CNTControlBase 用于配置系统计数器，并且在支持 TrustZone 的系统上仅限安全访问。此帧中的寄存器如下表所示：

| 寄存器 | 描述 |
| --- | --- |
| CNTCR | 控制寄存器，包括：计数器使能；计数器缩放使能（Armv8.4-A 或更高版本）；更新频率选择；调试时停止控制（在调试器请求时停止计数器递增）。 |
| CNTSCR | 使用缩放时的递增值（Armv8.4-A 或更高版本） |
| CNTID | ID 寄存器，报告实现了哪些特性。 |
| CNTSR | 状态寄存器。报告定时器是运行还是停止。 |
| CNTCV | 报告当前计数值。只返回计数的整数部分。 |
| CNTFID\<n\> | 报告可用的更新频率。 |

要启用系统计数器，软件必须选择一个更新频率并设置计数器使能。

CNTReadBase 是 CNTControlBase 的副本，只包含 CNTCV 寄存器。这意味着 CNTReadBase 只报告当前系统计数值。然而，与 CNTControlBase 不同，CNTReadBase 对非安全访问是可访问的。这意味着非安全软件可以读取当前计数，但不能以其他方式配置系统计数器。

## 6. 外部定时器

## 7. 使用 Arm Development Studio 的示例

本指南的这一节包含一个简短的示例（可作为 zip 文件下载），用于演示系统计数器的配置以及使用 TVAL 和 CVAL 生成中断。

该示例需要 Arm Development Studio。如果你还没有 Arm Development Studio 的副本，可以下载评估版。

该示例包含一个 ReadMe.txt 文件，其中列出了包含的文件，以及构建和运行示例的说明。

在 main.c 中是配置定时器的代码。浏览 main()，它以以下内容开始：

```c
//
// 配置中断控制器
//
rd = initGIC();
// 安全物理定时器 (INTID 29)
setIntPriority(29, rd, 0);
setIntGroup(29, rd, 0);
enableInt(29);
// 非安全 EL1 物理定时器 (INTID 30)
setIntPriority(30, rd, 0);
setIntGroup(30, rd, 0);
enableInt(30, rd);
```

前面的代码配置 GIC。GIC 的操作超出了本指南的范围，但配置 GIC 是生成定时器中断所必需的。

函数 initGIC() 执行中断控制器的顶层初始化。以下调用配置并启用与安全物理定时器和非安全 EL1 物理定时器相关的中断源。每个中断配置如下：

- Group 0。这意味着中断将作为 FIQ 发出信号。
- 优先级 0。这是 GIC 架构中最高的优先级值。
- 已启用。这允许中断向内核发出信号。

接下来，初始化系统计数器，如下所示：

```c
//
// 配置并启用系统计数器
//
setSystemCounterBaseAddr(0x2a430000); // 系统计数器的地址
initSystemCounter(SYSTEM_COUNTER_CNTCR_HDBG,
                  SYSTEM_COUNTER_CNTCR_FREQ0,
                  SYSTEM_COUNTER_CNTCR_nSCALE);
```

第一个调用设置系统计数器的位置，以便驱动程序函数可以访问它的寄存器。此地址基于 Arm Base Platform Model。关于此模型内存映射的更多信息可以在《Fast Models Reference Manual》中找到。

第二个调用写入 CNTCR 寄存器。代码选择频率更新方案 0，禁用缩放，并设置使能位。在此之后，系统计数将开始递增。

接下来 main() 有以下内容：

```c
//
// 配置定时器
//
// 配置安全物理定时器
// 使用 CVAL/比较器设置定时器触发的绝对时间
current_time = getPhysicalCount();
setSEL1PhysicalCompValue(current_time + 10000);
setSEL1PhysicalTimerCtrl(CNTPS_CTL_ENABLE);
// 配置非安全物理定时器
// 使用 TVAL/定时器在 X 个 tick 后触发定时器
setNSEL1PhysicalTimerValue(20000);
setNSEL1PhysicalTimerCtrl(CNTP_CTL_ENABLE);
```

前面的代码配置了两个定时器：

- 使用 CVAL 设置安全物理定时器 CNTPS。
- 使用 TVAL 设置非安全 EL1 物理定时器 CNTP。

然后 main() 中的代码等待两个中断都生成后才退出。

中断处理器也在 main.c 中：

```c
void fiqHandler(void)
{
  uin32_t ID;
  // 读取 IAR 以获取被送入中断的 INTID
  ID = readIARGrp0();
  printf("FIQ: Received INTID %d\n", ID);
  switch (ID)
  {
    case 29:
      setSEL1PhysicalTimerCtrl(0); // 禁用定时器以清除中断
      printf("FIQ: Secure Physical Timer\n");
      break;
    case 30:
      setNSEL1PhysicalTimerCtrl(0); // 禁用定时器以清除中断
      printf("FIQ: Non-secure EL1 Physical Timer\n");
      break;
    case 1023:
      printf("FIQ: Interrupt was spurious\n");
      return;
    default:
      printf("FIQ: Panic, unexpected INTID\n");
  }
  // 写入 EOIR 以停用中断
  writeEOIGrp0(ID);
  flag++;
  return;
}
```

中断处理器读取 GIC 的中断确认寄存器（IAR）以获取已送入中断的 ID。根据返回的值，处理器随后禁用相应的定时器以清除中断。另一种方法是设置 IMASK 并屏蔽中断，或更新比较器。

最后，中断处理器写入 GIC 的中断结束寄存器（EOIR）。这会更新 GIC 中针对已送入中断的内部状态机。

## 8. 知识自测

以下问题将帮助你检验你的知识：

**CNTFRQ_EL0 由硬件自动设置以报告系统计数的频率。对还是错？**

错。由 EL3 中的启动软件负责用正确的值填充该寄存器。

**描述配置给定定时器的两种方式。**

- TVAL 设置定时器在 X 个 tick 后触发（其中 X 是所写入的值）。
- CVAL 将定时器中的比较器设置为一个绝对值，当计数达到该数字时定时器触发。

**在中断处理器中，软件如何清除定时器中断？**

它可以设置 IMASK（屏蔽中断），可以清除 ENABLE（禁用定时器），或更新 CVAL/TVAL。

**通用定时器中断具有边沿触发还是电平敏感的语义？**

电平敏感。

**当通用定时器用于生成事件流时，事件的速率是如何控制的？**

EVNTI 通过选择计数中哪个位必须改变才能生成事件来控制事件速率。EVNTDIR 控制是该位的 0 到 1 还是 1 到 0 转换触发事件。
